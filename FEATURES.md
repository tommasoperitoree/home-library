# Features roadmap

Living backlog of what the app could do with data the spreadsheet already has
but the app doesn't use yet, plus bigger structural additions (write support).
Update this file as items move between stages — it's meant to be referenced
during work, not just written once.

Status: 💡 idea → 🚧 in progress → ✅ done → ⏸️ blocked

---

## Infrastructure

| Item | Status | Notes |
|---|---|---|
| Apps Script write endpoint (`doPost`) | ✅ done | Shared foundation for add-book, lending, and any future mutation. `addBook` action live and tested against production (both via curl and the browser form). Accepts title-only, isbn-only, or both. |
| Write-endpoint auth | ✅ done | Token check in place (`WRITE_TOKEN` script property). Since the Apps Script source + the webapp's JS are both public (public repo, GitHub Pages), a token embedded in client code isn't a real secret — it only blocks casual/bot abuse of the bare URL, not a motivated visitor reading page source. Acceptable tradeoff for a family app; revisit if that changes. |
| Book row stable ID | 💡 idea | Books sheet has no equivalent of the Loans sheet's `LoanID`. `handleSetHeldBy`/`handleAddBook` currently match by exact Title (first match), same limitation the pre-existing menu tooling already had — fine for now, revisit if duplicate titles cause a wrong-row edit. |
| ISBN enrichment trigger | ✅ done | `runEnrichmentBatch` in `apps-script/enrich.gs`, time-driven trigger (every 1 min). Finds Books rows with an ISBN but blank Title (scan-only adds), looks up OPAC SBN → Open Library fallback → cover search (Open Library + Google Books), fills in Title/Author/Publisher/Year/Language/Subjects/Cover URL. Ported from the standalone `enrich_books_from_isbn.py` (Airtable-based, now unused). Live-tested end to end (including a transient-fetch-error retry fix — see `apps-script/enrich.gs` history). A **confirmed** miss (both sources responded, neither has a record) now moves the row to ToReview (`ReviewStatus` "Manca Titolo") and deletes it from Books instead of leaving a "⚠️ ISBN non trovato" placeholder title cluttering the live family-facing Catalogo — per explicit decision. `migrateStuckNotFoundRows_oneOff` in the same file is a one-off to run once, to migrate any rows already stuck with the old placeholder from before this change. **ToReview sweep:** each run now also moves ToReview rows that have been filled in (ReviewStatus "Pronto"/"Manca Autore") to Books, and re-looks-up rows still missing a title (blank/"Cercando...", and "Manca Titolo" at most once a day — the date is stamped in ScanNote). Moving bumps Copies instead when Books already has that ISBN on the same shelf. Overlapping trigger runs are skipped via the document lock. |
| Legacy iOS Shortcut endpoint | ✅ done | `doGet`/`doPost` in `apps-script/api.gs` dispatch on request shape: a `secret` param (checked against the `WEBAPP_SECRET` script property) routes to the restored Shortcut flow — scan → ToReview staging → inline enrichment via `enrichSingleRow`/`runEnrichment` (`apps-script/EnrichISBNBooks_v2.gs`, not tracked in git, still live in the Apps Script project) — while `token`+`action` keeps using this app's own direct-to-Books flow. Live-tested (fresh scan + same-shelf copy-increment). **Known issue:** duplicate-ISBN detection across the full Books sheet is unreliable on a large sheet (~1070+ rows) — occasionally misses a real duplicate, not yet root-caused (possibly a timing/formula-recalculation interaction, not purely a logic bug). Low severity: worst case is a redundant ToReview entry, never a duplicate in Books itself, since moving ToReview → Books is still a manual, human-reviewed step. **Now:** a scan that enrichment finds is moved from ToReview to Books in the same request (`_moveToReviewRowToBooks_`); only not-found ISBNs stay in ToReview. |
| Books row Status/Active Loans formulas on new rows | ✅ done | `_setComputedStatusFormulas_` in `apps-script/api.gs` sets the same `IF`/`SUMPRODUCT` formulas `_restructureBooks` (HomeLibrary_v2.gs) sets for pre-existing rows, on any row `handleAddBook`/`handleSetHeldBy` touches — so a book added via the webapp, Shortcut-via-ToReview-move, or the original menu tooling all compute "In prestito"/"Con X" the same way. Previously, webapp-added rows had blank Status/Active Loans forever. |
| Authors sheet `_splitAuthors` fix | ✅ done | `HomeLibrary_v2.gs` now also splits on `"; "` (author + illustrator pairs), not just `", "` — 4 real cases found where 2 people were being counted as 1 bogus author, undercounting 2 people (`Ines Belski Lagazzi`, `Stelio Martelli`/`Stefania Stefani`) who also appear correctly elsewhere as solo credits. Verified against all known cases. 2 rarer `"Name1 e Name2 Surname"` cases left as manual sheet fixes (too risky to generalize from 2 examples). |
| `parseLoans`/`books` endpoint missing Loans fields | ✅ done | Now exposes `library`/`expectedReturn`/`notes` alongside the existing `id`/`book`/`lentBy`/`borrowedBy`/`dateLent`. Shown in the lending actions sheet (expected return date); overdue-badge logic can build on `expectedReturn` next. |

| **Cover URL** | 🚧 in progress | Exposed by `parseBooks` (`cover` field) and shown at the top of the book detail sheet (`.detail-cover`, `js/app.js`/`css/style.css`) when present. Catalogo's row list itself still shows the decorative shelf-color bar, not a thumbnail — that'd be the next step if wanted. |
| **Subjects** | 🚧 in progress | Exposed by `parseBooks` (`subjects` field) and shown in the book detail sheet's metadata grid. No filter chips in Catalogo yet (still just an idea). |
| **SeriesName / SeriesOrder** | ✅ done | Exposed by `parseBooks` (`sn`/`so` compact fields), shown as a gold pill badge next to the shelf badge (`.book-series`, `renderBookRow` in `js/ui.js`). Data applied to production via `apps-script/one_off_series_mapping.gs` (also stripped the now-redundant volume number out of each title, e.g. "1: Harry Potter e la pietra filosofale" → "Harry Potter e la pietra filosofale") — live-verified in browser: badges, clean titles, and correct Catalogo letter-bucket all confirmed. See that file for which series were identified and why some were deliberately left out (same-title duplicate copies, unclear translated-edition numbering). More series can be added the same way later (it's just a title→{series,order} map, re-run is idempotent). |
| **ReadBy** | 🚧 in progress | List of family members, stored as "Papà, Tommi" (comma + space, `FAMILY_MEMBERS` order — same format as a Sheets multi-select dropdown). Exposed by `parseBooks` as `rb`; book detail sheet shows "Letto da" and a "📖 Segna come letto" / "✓ Letto — togli" toggle for the current member (`setRead` action). `migrateBooksSheet_oneOff` reformats existing values and adds the family-member dropdown; "Allow multiple selections" has to be ticked by hand (not settable from Apps Script). |
| **Publisher / Year** | ✅ done | Exposed by `parseBooks` (`pub`/`year`) and shown in the book detail sheet's metadata grid, alongside ISBN (already exposed for the scan flow, now also shown here as a display field). |
| **Copies** | 🚧 in progress | Every path that adds a Books row now defaults Copies to 1 (`handleAddBook`, `_appendBooksRow_`); blanks backfilled by `migrateBooksSheet_oneOff`. Data-model rule now settled: same ISBN scanned at the **same** shelf = another physical copy → `Copies` is bumped by 1 on the existing Books row (no new row, no ToReview trip). Same ISBN at a **different** shelf = a genuinely distinct copy living elsewhere → its own row, not a duplicate. Implemented in the legacy Shortcut's `_handleAddBookShortcut`/`_incrementCopiesShortcut_` (`apps-script/api.gs`). Not yet applied to the webapp's own scan flow, since that scanner doesn't currently ask which shelf you're scanning into before each ISBN — would need that UI first. Catalogo display still doesn't reflect `Copies > 1` specially (e.g. "2 copie disponibili").  |
| **Status** | ✅ done | Formula: "In prestito" > "Con <Held By>" > "In libreria" (was blank when on the shelf). App detail sheet says "In libreria · <shelf>". Existing rows updated by `migrateBooksSheet_oneOff` (`apps-script/api.gs`). |
| **Active Loans** (Books sheet) | ✅ done | It's a formula over the Loans sheet; now shows "-" instead of 0 (Status reads it via `N()` since text > 0 is TRUE in Sheets). |
| **Expected Return** (Loans sheet) | ✅ done | Overdue badge ("in ritardo da N giorni") on active loans, in the Prestiti tab. |
| **Notes** (Books sheet) | ✅ done | Exposed by `parseBooks` (`notes`) and shown in the book detail sheet when present. |
| **Notes** (Loans sheet) | ✅ done | Shown under each loan in the Prestiti tab. |

## Structural features

| Feature | Status | Notes |
|---|---|---|
| **Add book endpoint** | ✅ done | `doPost` action `addBook` in `apps-script/api.gs`, appends a row to the Books sheet. Header-mapped (robust to column reordering); accepts title and/or isbn. |
| **Add book UI (webapp)** | ✅ done | "+ Aggiungi libro" form in Catalogo calling the endpoint above, with optimistic local update. |
| **Scan ISBN UI (webapp)** | 🚧 in progress | "📷 Scansiona ISBN" in Catalogo. **Pick the shelf first** (remembered in `hl_scan_shelf`, changeable mid-session via "Cambia"), then continuous scanning restricted to barcode formats (EAN-13 etc., native `BarcodeDetector` when available). Each scan beeps/vibrates and calls `scanIsbn` (`apps-script/api.gs`), which looks the ISBN up inline and files it **directly on the chosen shelf**: found → Books (shown immediately with title/author), confirmed not found → ToReview "Manca Titolo", lookup error → Books with blank Title for `runEnrichmentBatch` to retry. A status banner + per-scan log give feedback for every outcome, including non-ISBN barcodes. **Already-catalogued ISBN** (checked locally first, then server-side, ISBN-10/13 normalized) → "Già in libreria" popup with title, cover and every shelf it's on: copies stepper per shelf (`setCopies`), "Aggiungi una copia in un altro scaffale" (`addCopyToShelf`, copies the existing row's metadata), "Chiudi e continua". Scanning is paused while the popup is open. Needs a phone-camera test pass. |
| **iOS Shortcut add-book flow** | ✅ done | Already existed (built before this webapp effort, in `HomeLibrary_v2.gs`/`WebAppEndpoint_v2.gs`/`EnrichISBNBooks_v2.gs`, discovered via the sheet's own auto-generated README) and in active family use — a real Shortcut scans → secret-gated POST → ToReview → inline enrichment. Temporarily broken when `WebAppEndpoint_v2.gs` was deleted to resolve a `doPost` collision; restored by merging its logic into `apps-script/api.gs` (see Infrastructure table). A separate, intentionally different pipeline from the webapp's own scan feature above (ToReview-staged + immediate enrich vs. Books-direct + timer enrich). |
| **Book detail + lending sheet** | 🚧 in progress — PR `feature/lending-ui` + stacked PR `feature/book-detail-view` | One unified bottom sheet (`openBookDetailSheet`, `js/app.js`), opened by tapping any book row (Catalogo/Io/Famiglia — `renderBookRow`'s new `onOpen` callback, `js/ui.js`) — merged by explicit decision rather than two separate screens/triggers. Shows: cover image if present (`.detail-cover`), title/author, a metadata grid (Series #order, Shelf, Language, Publisher, Year, ISBN, Subjects — `.detail-meta`), Notes if present, then current status (an active loan always takes precedence over the informal Held By marker, same precedence as the sheet's own Status formula) and state-dependent lending actions: available → "Tieni tu"/"Presta a qualcuno" (the latter opens a small borrowedBy+expected-return form, `lendBook`); held → "Rimetti a posto" (`setHeldBy`); on loan → "Segna restituito" (`returnBook`). All three lending actions do optimistic local `state.books`/`state.loans` updates. Backend support: `doPost` actions `setHeldBy`/`lendBook`/`returnBook` in `apps-script/api.gs`, plus `parseBooks`/`parseLoans` now expose the extra display fields (`isbn`/`pub`/`year`/`cover`/`subjects`/`notes` and `library`/`expectedReturn`/`notes` respectively). **Design rule, per explicit decision:** `Library` is always the book's permanent home shelf and is *never* written by any lending action — only `Held By` or a new Loans row changes. This also surfaced a real data-quality gap in the live sheet: several pre-existing rows have a **blank** Library whenever `Held By` is set (Library got cleared instead of preserved); unrecoverable now, a one-off manual sheet fix, not scriptable. Browser-tested (all 3 lending states, form validation/cancel, metadata grid layout) against the current (pre-redeploy) backend — the UI itself is solid; actual writes and the new display fields still need the redeploy + a live test pass. |
| **Prestiti tab (whole-house loans)** | 🚧 in progress — branch `feature/loans-tab` | New bottom-nav tab listing **every** active loan, not just the current user's: book, who lent it (face + name) → who has it, since when, expected return, notes, shelf. Summary count + "N in ritardo"; filter chips by lender; overdue loans first with an "in ritardo da N giorni" badge (from `expectedReturn` — covers the earlier overdue-badge idea), then oldest first. Tapping a loan opens the book detail sheet (where "Segna restituito" is). **"+ Nuovo prestito"** at the top opens a catalog picker (search only filters; books already on loan excluded) → the book's detail sheet opens straight on the lend form (asking "Chi sei?" first if no member is picked). A loan whose title isn't in Books still opens (stub detail sheet); returning it asks for a shelf and `returnBook` creates the missing Books row there. |
| **Change shelf + put-back shelf confirmation** | 🚧 in progress — branch `feature/change-shelf` | Book detail sheet has a "🗂️ Cambia scaffale" (or "Assegna scaffale" when Library is blank) button → shelf `<select>` → new `doPost` action `setLibrary` (`apps-script/api.gs`). "✅ Segna restituito" and "↩️ Rimetti a posto" no longer act immediately: if the book has a home shelf (Books.Library, falling back to the loan's recorded Library when Books.Library is blank) they ask "Rimetterlo in X?" with "Sì" / "Altro scaffale"; with no known shelf they go straight to the shelf picker. The chosen shelf is sent as an optional `library` field on `returnBook`/`setHeldBy` (only when it differs from the current one), so the put-back is a single request. **Supersedes the earlier "Library is never written" rule:** lending/holding still never changes Library implicitly — it's only written when the user explicitly picks a shelf. Needs Apps Script redeploy + live test. |

## Already shipped

- Core PWA: Io/Catalogo/Famiglia tabs, bottom sheet, offline cache (`sw.js`).
- Live data via Apps Script (`doGet`), with shelf/heldBy/active-loans column mapping fixed to match the real sheet headers.
- Daily GitHub Action sync (`scripts/sync.py`) as the bundled offline fallback.
- Catalogo: alphabetical list with letter-section headers (leading Italian/English articles ignored for sorting, e.g. "Il senso religioso" files under S), sub-sorted by shelf within each letter so same-shelf books cluster together (`sortCatalogBooks`/`groupLetter` in `js/app.js`, `renderGroupedBookList` in `js/ui.js`).
- Book spine color is now a stable per-shelf color (`shelfColor` in `js/data.js`), replacing the old purely-decorative per-row-index color cycle.
- Tapping any book row (Catalogo, Io, Famiglia) opens a unified book detail + lending sheet — see the row above.
- No more forced "Chi sei?" gate on launch. Catalogo is the landing tab (first-ever visit); Famiglia is open to anyone too. Picking a member is only prompted where it's actually needed: switching to the Io tab, or tapping "Tieni tu"/"Presta a qualcuno" on a book before any member has ever been picked (`ensureUser` in `js/app.js` for Io, an equivalent inline `chooseUser` mode in the book detail sheet — both preserve whatever content was already on screen, e.g. the book's own info, rather than wiping it). Per explicit decision.
- Each family member has a real face icon (`icons/family/<name>.svg`, added by the user) instead of an emoji — shown in the member grid, the Famiglia list, the member detail sheet header, and a new Io-tab header (`.io-header`) next to the greeting. Tapping that face icon reopens the "Chi sei?" chooser (`renderChooser` in `js/app.js`, factored out of `ensureUser`) to switch identity at any time, not just when none is set.
- `MEMBERS` (`js/data.js`) is ordered Papà, Mamma, Tommi, Vitto, Checco, Giachi, Gio, Ale — per explicit decision; every member list in the app follows this order since they all iterate `MEMBERS` directly.
- The app remembers which tab you last had open (`hl_last_tab` in localStorage, `getLastTab`/`setLastTab` in `js/data.js`) and reopens there, falling back to Catalogo if nothing's been saved yet (e.g. first-ever visit).
